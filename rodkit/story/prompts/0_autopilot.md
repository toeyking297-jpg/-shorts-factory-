# ขั้นตอนอัตโนมัติ: "สร้างคลิปความยาว N นาที"

ทำเองทั้งหมดจนได้ไฟล์คลิป
- ห้ามส่งพล็อตให้เจ้าของช่องเลือก
- ห้ามขออนุมัติบท
- ไม่เผยแพร่ เว้นแต่สั่ง
- ทุกขั้นบันทึกสถานะที่ `story/runs/<ID>/state.json` ถ้าสะดุดให้ทำต่อจากขั้นที่ค้าง

## ขั้น A · อ่าน (ไม่ข้าม)
อ่าน 3 อย่างนี้ก่อนเริ่ม:
- `GUIDE.md` ข้อ 0 (แนวช่อง) และข้อ 4–5 (คาสต์และข้อจำกัดการผลิต)
- `memory/stories.json` (เรื่องเก่า วิธีเฉลย และความเห็นเจ้าของช่อง)
- `owner_taste` ในไฟล์เดียวกัน

## ขั้น B · คิดภายใน
1. คิดแนวคิดสั้น 6–10 แบบ บรรทัดละ 1 แนว (หัวข้อหมุนเวียนตาม GUIDE ข้อ 0) แล้วเลือกเรื่องที่แข็งที่สุดเอง
2. ทุกแนวต้องต่างจากเรื่องเก่าที่ "เหตุการณ์และวิธีจบ"
   - เปลี่ยนแค่อาชีพหรือสถานที่ = ยังถือว่าซ้ำ
3. เก็บแนวที่คัดทิ้งพร้อมเหตุผลไว้ที่ `runs/<ID>/ideas.md`
4. เรื่องที่เลือกต้องตอบ 7 ข้อนี้เป็นเหตุการณ์ที่เห็นเป็นภาพได้ (ไม่ใช่คำนามธรรม):
   1. ตัวละครต้องการอะไร
   2. ใครเข้าใจอะไรผิด หรือยังไม่เห็นบริบทอะไร
   3. ทำไมความเข้าใจนั้นดูสมเหตุสมผลในตอนแรก
   4. ตัวละครเลือกทำอะไร
   5. การเลือกนั้นสร้างผลอะไร
   6. หลักฐานหรือเหตุการณ์ใดทำให้มุมมองเปลี่ยน
   7. ตอนจบตอบสิ่งที่เปิดไว้อย่างไร และให้ความรู้สึกอะไร
5. วางเรื่องย้อนจากตอนจบ
   - กำหนดก่อนว่าตอนท้ายคนดูจะเข้าใจอะไรใหม่
   - แล้วปูหลักฐานไว้ก่อนอย่างเป็นธรรม
   - เลือกวิธีเปิดข้อมูล 1 แบบ:
     - (ก) คนดูรู้ทีหลัง
     - (ข) คนดูรู้ก่อนตัวละคร
     - (ค) ทุกฝ่ายรู้เหตุการณ์แต่ตีความต่างกัน

## ขั้น C · เขียน → ตรวจ → แก้
1. เขียน `stories/<ID>.story.json` ตาม `3_write.md`
   - ใส่ช่อง `perspective` (ดู SCHEMA)
   - ใส่ `target_sec`
2. รัน `story_tool check` ต้องได้ ERROR 0
3. รัน `story_tool dup` ต้องไม่ "ซ้ำมาก"
4. ผู้ตรวจรอบใหม่ใช้ `4_review.md` (9 ข้อ + เกณฑ์ 85)
   - ผู้ตรวจต้องกล้าปฏิเสธบทได้
   - ต้องชี้ข้อบกพร่องจากเหตุการณ์จริงในบท
5. ถ้ามีช่องโหว่ ให้แก้ที่เหตุการณ์ก่อนแก้ภาษา
   - แก้ได้ไม่เกิน 2 รอบต่อพล็อต
   - ถ้ายังไม่ผ่าน เปลี่ยนพล็อต (รวมไม่เกิน 3 พล็อต)
   - ถ้าครบ 3 พล็อตแล้วยังไม่ผ่าน ให้ผลิตพล็อตที่คะแนนสูงสุด และรายงานจุดอ่อนตามจริง

## ขั้น D · ผลิต (ใช้ระบบเดิม)
1. ล็อกบท แล้วสร้าง ep.json ด้วยสคริปต์ generator
   - ใส่ `targetSec`
   - ช็อตเงียบเป็นจุดยืดหดเวลา
   - ใส่ `lockDur: true` ในช็อตที่ห้ามเปลี่ยนความยาว
2. ทดลองผลิตในเครื่อง: `produce --dry --no-render` → ดูรายงานเครดิตและความยาวโดยประมาณ
3. ทำ storyboard แล้วแก้ภาพที่ผิด
   - เรนเดอร์ใหม่เฉพาะช็อตที่แก้ (`--stills`)
4. push job ครั้งเดียว ระหว่างผลิต ระบบจะ:
   - สร้างเสียงจริงและวัดความยาว
   - ปรับเฉพาะช่วงภาพและความเงียบให้ได้ `targetSec`
   - ไม่เร่งเสียง ไม่ตัดคำพูด
5. ตรวจคลิปจริง:
   - ความยาว ±2 วินาทีจากเป้า
   - ภาพไม่กระโดดนอกจุดตัดช็อต
   - เสียงจบครบ
   - ถ้าความยาวเกินเพราะเสียงพูด ให้ย่อประโยคที่ซ้ำแล้วผลิตใหม่ (สร้างเสียงเฉพาะประโยคที่แก้)
6. ถ้าติดโควตา ติดล็อกอิน หรือสร้างไฟล์ไม่สำเร็จ ให้รายงานสั้นๆ ว่าติดขั้นไหน
   - ห้ามบอกว่าเสร็จถ้ายังไม่มีไฟล์
   - ห้ามซื้อเครดิตเพิ่ม

## ขั้น E · ส่งงาน (แสดงเท่านี้)
- ชื่อคลิป
- เรื่องย่อ 1–2 ประโยค
- ไฟล์คลิปและความยาวจริง (ส่งปกและแคปชั่น 5 แฮชแท็กที่มี #ดูเพลิน ไปด้วย ตามมาตรฐานช่อง)
- ปัญหาคงค้างที่มีผลต่อการใช้งาน (ถ้ามี)

จากนั้นบันทึกเรื่องลง `memory/stories.json` (ฟิลด์ตาม SCHEMA)
เมื่อได้ความเห็นเจ้าของช่อง ให้เพิ่มลง `owner_feedback` และ `owner_taste`
